# ClearFrame agent instructions

ClearFrame now uses **FFFrames for every active render**. Begin with `skills/clearframe/SKILL.md`, then `skills/clearframe-library/SKILL.md`. Use `skills/clearframe-engine/SKILL.md` for project commands and `skills/clearframe-fframes/SKILL.md` plus `fframes/AGENTS.md` for renderer changes.

- Author one storyboard, using `block` and validated `props`. Run `playbooks`, `blocks`, `treatments` and `sketch` before inventing a scene.
- Adapt structure to the story. Playbooks and treatments are reusable starting points, not limits on possible films. Source material (reports, recordings) goes through `ingest`; references through `reference`; see `skills/clearframe-direction/SKILL.md`.
- New palettes, treatments, type voices, sketches and playbooks are files in `library/` (see `library/README.md`); engine code is for new capabilities. A project's `library/` or `--library DIR` overrides built-ins, JSON only.
- Films are not slide decks (read `skills/clearframe-cinema/SKILL.md` and `docs/cinema.md`; `critique` prints a cinema score): draw mechanisms (`canvas`), use plates, tones, camera and graphic transitions, and run `critique` before rendering.
- Choose palette, type voice (`type`, usually from the treatment; `types` lists them), motion preset/intensity and entrances explicitly. Follow `docs/style.md`; use `looks` to compare one scene across palettes. Keep slide counters out of film output.
- New GitHub code/assets must be MIT-licensed at the exact imported revision, with bundled notices/provenance; bundled fonts are SIL OFL 1.1 from google/fonts at a pinned revision with hashes in `fframes/assets/fonts/provenance.json`. Prefer independently implemented ideas over adding another renderer; see `docs/research/2026-github-video-patterns.md`.
- For speech-following text read `docs/speech.md`. Never call interpolated timestamps measured. Final kinetic/captioned scenes require word timings tied to the current audio hash; `align --whisper` measures them locally for free.
- Keep factual text, charts and labels native. Every displayed number needs visible attribution and a `sources` entry. Never present sample figures or fictional quotes as evidence.
- For brand-sensitive art, use imagegen to explore materials and geometry, then rebuild selected ideas with palette tokens and native fonts; see `docs/image-direction.md`. Generated stills are a regular tool for places: depth plates (`layers: true` assets, `plates` on a canvas) put the camera inside painted scenes. Never put text, numbers or evidence in an image, and run `plan` first. Generated footage is sparing (default review threshold 20% of runtime). Read `docs/continuity.md` and the Gemini Omni skill. Use references and the film palette; review both joins. Discard generated clip audio and keep the shared mix. Footage-led films (sizzle, trailer, brand spot) follow `docs/hero-footage.md`: approved keyframe stills before any video call, cheap drafts before one final render, and `seedance2_5` (Runway) or Veo per shot.
- Work guided (stop at the human checkpoints) unless asked for a one-shot film; in one-shot mode decide and log each checkpoint in DIRECTION.md (`decide DIR rNNN` for the rough cut and final). See `docs/collaboration.md` and `checkpoints DIR`.
- Show motion before bespoke work: the first look is a full-length rough cut (`draft DIR --rough`) from existing blocks, captions and declared `placeholder` beats; drawing every beat and reviewer rounds come after the person's notes. `--rough` relaxes only declared stand-ins, never facts, sources, audio or timing.
- Feedback goes through `review/` (`docs/editing.md`, `skills/clearframe-review/SKILL.md`): record notes against the revision watched (`note --rev`), edit only the note's beats, `revise` for a before/after candidate, and record only what the person actually said with `accept`/`reject --by NAME --said`. Applied is not accepted. Edit recorded narration with `cut`/`uncut`/`split`/`merge`, never by changing `vo`.
- Run `plan` before paid generation and honor the user's scope/budget. No paid calls merely to test code.
- Render `sheet`, open the image, run `check`, then render/review the complete MP4. Use `review DIR` for decoded frames around cuts and word boundaries, and `qa DIR` for time bugs a still cannot show (one-frame pops, stretches where the picture barely changes, world seams that jump, export tags, loudness, the music drop) plus a 360 px phone sheet. Passing diagnostics alone does not establish visual quality, accurate transcription or factual correctness.
- Native frame output must depend only on frame number and prepared inputs. No live generation, random state or wall-clock animation in `render_frame`.
- The library holds sources, not outputs. Never commit renders, contact sheets, review evidence or receipts; they go to `build/`. Add one curated example per capability, judge its rendered frames against professional references (an FT or Bloomberg chart, a premium brand film) before committing, and keep on-screen copy product-native: no disclaimers about what a picture does not measure. `test/repo-hygiene.test.mjs` enforces the binary allowlist.
- Preserve unrelated changes. Archived browser source is for recovery only; no fallback renderer is active.
- Native builds use one Cargo job and at most two supported workers. `buildNative` automatically gates compilation; on this 8 GB Mac also wrap full renders and full test suites with `codex-heavy`. For an outer-gated render pass `env CLEARFRAME_HEAVY_HELD=1` after `--` to avoid a nested lock. Reuse the warm cache and retain at least 20 GiB free before expensive work. Full high-resolution renders need at least a five-minute harness allowance or resumable execution, including audio finishing; keep waiting on the same process.
- `docs/guide.html` is the living guide: how ClearFrame works and how to prompt it. When a feature, command or rule changes, update the guide in the same change (its header comment lists the sources of truth), along with the CHANGELOG.
- This is an experimental project: tests are fast smoke checks that help development, not exhaustive edge-case coverage. Add a test when it saves debugging time; don't add them for completeness.
- When independent custom scene work benefits from parallel agents, give each agent one owned native module and the storyboard/visual brief; avoid concurrent heavy builds.

Useful commands: `node engine/cli.mjs help`, `doctor`, `new DIR --playbook NAME --treatment ID`, `ingest DIR --markdown|--audio`, `reference VIDEO`, `themes`, `treatments`, `sketch`, `critique DIR`, `voice DIR --draft`, `align DIR --whisper`, `sheet DIR --draft [--grid]`, `check DIR --draft`, `render DIR --draft`, `qa DIR`, `beatmap DIR`, `paper DIR`, `draft DIR --rough`, `note DIR`, `revise DIR --note ID`, `diff DIR`, `runlog DIR`. Full Node contract tests: `/Users/brandon/.local/bin/codex-heavy -- npm test`; focused tests can run directly. The review loop end to end (native, local Whisper): `node scripts/review-e2e.mjs OUT`.
