# Inventory view design

The subject is a working library of explanatory pictures. The interface should let a director find a visual operation and let an implementer see its readiness and dependencies.

Palette: mist `#e8f0f4`, white paper `#ffffff`, deep harbor ink `#183b49`, ocean blue `#245c9a`, plum `#79526f`, bronze `#86501c`. Blue identifies native graphics, plum identifies physical assets, and bronze identifies work priority. Text contrast takes precedence over category color.

Type: Georgia for the principal editorial heading; the operating system's sans-serif for all controls, records and body text. No font download. Keep prose under 75 characters where possible.

Layout: a concise introduction beside an actual retained Blender poster, followed by a compact library shelf and a search/filter bar. The inventory is an expandable list, not 62 identical cards. Each row exposes name, medium, readiness and priority; expansion reveals the mechanism, parameters, reuse, evidence and constraints. Source records are available at the end.

The characteristic visual is the physical mobile beside the vocabulary of flat data marks. Existing media is labeled as existing; proposed work receives no fabricated render preview. Filters respond immediately without page navigation. No autoplay, decorative animation, remote dependencies or hidden data requests.

Review against brief: avoid an investment dashboard appearance because this is a creative production plan. Avoid Fidelity branding because the work is an independent general-purpose library. Use images only for actual retained assets; the proposed catalog remains a written design specification. Preserve accessible summaries, native controls, keyboard focus and a mobile single-column layout.
