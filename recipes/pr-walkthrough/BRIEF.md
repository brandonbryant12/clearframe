# Explain a pull request

Audience: Engineers, reviewers and product colleagues

Inputs: The actual PR diff, verified before/after behavior, and validation evidence

Illustrative system only: rebuild the nodes, edges, steps and narration from the actual diff. Keep component ids stable across beats so the diagram morphs instead of redrawing; cue steps to narration with say once the voice is recorded. Do not imply deployment or runtime proof from source changes; cite the tests or runs that verified the change. Use the business treatment (film camera: none).
